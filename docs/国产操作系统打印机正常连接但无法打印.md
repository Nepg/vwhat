# 统信 UOS / 麒麟 V10 打印机连通正常但无法打印故障排查文档

## 一、故障现象

### 1.1 系统侧状态

操作系统：统信 UOS、麒麟 V10

1. 可通过 ICMP 协议 ping 通打印机 IPv4 地址；
2. 系统打印管理模块可完成打印机设备添加与连接识别；
3. 提交打印作业后，打印队列显示任务已发送，系统前端未弹出错误提示。

### 1.2 打印机侧状态

1. 打印机无物理动作响应（不走纸、打印头无动作、状态指示灯无变化）；
2. 本地打印队列中无滞留任务，设备无硬件故障告警；
3. 同一局域网内 Windows 设备可正常完成打印作业；
4. 此前设备可正常打印。

## 二、故障原因分类

以下为可能导致该故障的类别，具体原因需结合日志进一步确认：

1. CUPS 打印服务进程异常或打印队列缓存数据异常；
2. 打印临时缓存文件损坏或目录访问权限配置异常，作业数据无法下发至打印设备；
3. 打印机网络设备 URI 与设备当前 IP 地址不一致；
4. 打印驱动执行异常，作业数据格式转换失败；
5. 系统版本更新后，打印相关依赖库存在版本兼容性问题。

## 三、排查与修复流程

### 步骤 1：设备复位操作

1. 关闭打印机电源，静置 10 秒后重新上电启动；
2. 重启故障主机；

### 步骤 2：CUPS 服务重启与打印队列缓存清理

临时关闭操作系统防火墙

终端唤起快捷键：`Ctrl+Alt+T`，按顺序执行以下指令：

```bash
# 停止 CUPS 打印服务
sudo systemctl stop cups
# 清理打印队列缓存文件
sudo rm -rf /var/spool/cups/*
# 启动 CUPS 打印服务
sudo systemctl start cups
# 查看 CUPS 服务运行状态，确认状态为 active (running)
sudo systemctl status cups
```

执行完成后，提交测试页，观察打印是否恢复。

### 步骤 3：CUPS 日志采集与故障定位

执行以下命令实时监控日志输出，再提交一个打印任务：

```bash
sudo tail -f /var/log/cups/error_log
```

根据日志输出的关键字定位故障原因，对应关系如下：

| 日志关键字           | 故障释义                 | 对应处理步骤                                 |
| -------------------- | ------------------------ | -------------------------------------------- |
| `permission denied`  | 打印缓存目录访问权限不足 | 步骤 4                                       |
| `filter failed`      | 打印驱动过滤器运行异常   | 步骤 5                                       |
| `connection refused` | 打印机 9100 端口通信阻断 | 步骤 6                                       |
| `Invalid argument`   | 打印文件数据格式异常     | 使用纯文本文件测试，检查文件名是否含特殊字符 |

### 步骤 4：打印缓存目录权限修复

适用条件：日志报错包含 `permission denied`。

方案一（配置 ACL 权限）：

```bash
setfacl -m g:lp:rwx /var/spool/cups/tmp
setfacl -m d:group:lp:rwx /var/spool/cups/
```

方案二（临时全局放行，仅用于故障验证，不推荐长期使用）：

```bash
sudo chmod -R 777 /var/spool/cups
```

### 步骤 5：打印驱动更换或重装

适用条件：日志报错包含 `filter failed`。

1. 图形界面操作：在打印机属性中选择「更换驱动」，尝试 `Generic` 或 `Raw` 驱动；
2. 前往打印机厂商官网下载适用于统信 UOS / 麒麟 V10 的专用驱动包进行安装；
3. 安装通用打印驱动包：

```bash
sudo apt install printer-driver-all
```

### 步骤 6：网络端口连通性验证

执行以下命令，验证打印机 9100 端口是否可达：

```bash
nc -zv 打印机IP 9100
```

- 输出 `succeeded`：端口链路通畅；
- 连接失败：排查交换机端口配置、打印机网络服务状态及主机防火墙规则。

## 四、附录：CUPS 运维常用指令

```bash
# 查看 CUPS 服务运行状态
sudo systemctl status cups
# 查看全局打印队列及设备信息
lpstat -t
# 取消本机全部打印任务
cancel -a
# 重启 CUPS 服务
sudo systemctl restart cups
# 枚举本机识别的打印设备 URI 信息
lpinfo -v
```
